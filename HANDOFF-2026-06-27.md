## 3. How it works (pointers)

- **OTP backend** `api/internal/modules/user`: `RequestOTP`/`VerifyOTP`/`LoginByPhone`
  in `service.go`; `otp_repo.go`; phone normalized to E.164 (`+961` default). Indexes
  auto-created at startup.
- **SMS** `api/internal/platform/sms`: `Sender` port + `monty.go`/`twilio.go`/`log.go`;
  `New(Config)` selects by `SMS_PROVIDER`. Monty = `GET sms.montymobile.com/API/SendSMS`
  (X-Access-Token + `username`/`apiId` query; reply `{ErrorCode,Description,Id}`,
  `0`=ok). Config keys: `MONTY_USERNAME/API_ID/ACCESS_TOKEN/SENDER_ID(=Arya)/BASE_URL`.
- **Flutter auth** `app/lib/features/auth`: login offers **code or password**; signup
  phone→password→OTP. Wired datasource→repo→usecase→providers→controller.

## 6. Gotchas

- **`az` fails locally** (corporate-proxy TLS). Use **Azure Cloud Shell** (browser,
  pre-auth, no proxy). `git`/`gh`/`docker`/Go work via the Windows cert store.
- **Monty `-8 Invalid Source`** = unapproved sender **or** non-whitelisted caller IP
  (two separate controls). Approved sender so far: `Arya`.
- **OIDC subject is case-sensitive** — repo is `AliSleiman0/SalehCard` (capital S/C).
- **Cosmos firewall must include the NAT IP** (Route-All routes DB egress through it).
- Local `curl` to Azure/Monty needs `--ssl-no-revoke` (schannel revocation blocked by proxy).
- Dev egress IP `213.204.66.98` is whitelisted on Monty (for local testing); prod uses the NAT IP.
