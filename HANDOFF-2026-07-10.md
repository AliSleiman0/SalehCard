## Why this exists (context)

The v1 USDT design (PR #51) needs a watch-only **xpub** to derive a unique
deposit address per payment. The client is a casual custodial-Binance user and
could not produce an xpub after much back-and-forth (he sent a BEP20 address
`0x5e0a66cedc7688aab52c87dc02bff97f6575d7dc` first, then a Binance TRC20 deposit
address, then finally `TLRaHegyg2grMQqX85nJyCzbdRtvM5nCDn` — confirmed with him
character-for-character). So we built a second, env-switched **shared-address
mode**: every customer pays the one address; payment↔customer identity is an
**exact salted amount** (sub-cent counter salt, 1–9999 micro-USDT); anything
that matches no open payment lands in an **admin reconciliation queue**.

## What shipped (PR #68, merged 2026-07-10, commit a99e381)

- **Mode switch**: `USDT_XPUB` → derived (v1, unchanged) | `USDT_ADDRESS` →
  shared | both → refuses to boot in every env | neither → dark. Mode is
  stamped per-intent (`Intent.AddressMode`) so env flips mid-flight are safe.
- **Backend**: salt counter + unique partial open-amount index (+3-attempt
  resalt); `tron.TransferLister` port (trongrid + stub); watcher partitions by
  mode — `scanShared` = one chain call per address, strict exact-amount +
  BlockTime≥CreatedAt matching; unmatched transfers → new `usdt_deposits`
  collection; admin `GET /api/admin/payments/deposits`, `POST …/{id}/attribute`
  (atomic claim → idempotent wallet credit ref `deposit:<txHash>` → notify →
  audit `payment.deposit_attribute`), `POST …/{id}/ignore`. Boot index
  migration: `address_1` → unique partial `{addressMode:"derived"}` (verified
  applied on dev Mongo AND implicitly in prod via boot warnings absence —
  double-check `getIndexes()` on Cosmos, see DEVOPS-TODO §14a item 4).
- **Admin console**: Payments page → "Payments | Unmatched deposits" tabs,
  Attribute/Ignore modals (`payments.manage`), shared/derived badges,
  full-precision amounts.
- **Flutter**: `formatUsdtAmount` (6-decimal, trailing-zero-trimmed, min 2) for
  the deposit screen's copy+display — the old `toStringAsFixed(2)` would strip
  the identity digits; strengthened "send exactly" copy (EN/AR).
